# NextViper Reproducible Builds Specification

NextViper guarantees deterministic and reproducible compilation outputs across identical inputs.

---

## 1. Reproducibility Factors

A build is reproducible when the following four inputs match:
1. **Source Tree:** The identical source code and git commit.
2. **Lockfile (`nextviper.lock`):** Identical dependency resolution and cryptographic SHA-256 tree hashes.
3. **Compiler Toolchain:** Identical NextViper compiler version (`v1.0.0`).
4. **Target Environment:** Identical OS target and CPU architecture.

---

## 2. Lockfile Guarantees

The `nextviper.lock` file stores the exact SHA-256 integrity hashes of all packages:

```toml
# Auto-generated by NextViper Package Manager. DO NOT EDIT.
version = 1

[[package]]
name = "postgres_client"
version = "1.0.0"
checksum = "7f83b1657ff1fc53b92dc18148a1d65dfc2d4b1fa3d677284addd200126d9069"
```

If a package's contents on disk differ by even one byte from the locked checksum, `nextviper install` and `nextviper build` will abort with an integrity mismatch error (`NV205`).
